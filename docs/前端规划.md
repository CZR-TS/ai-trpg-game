# 前端规划：AI 双人跑团游戏（v2 重做版）

> 本文档定义前端架构、6 个视图、前端状态机、与后端对齐的接口契约、mock 策略、世界书导入流程、管理员/玩家分工。
> 当前阶段：纯静态原型（`public/`），`file://` 可直接预览，mock 驱动完整流程，无需后端。

---

## 0. 设计定位（Design Read）

- **类型**：交互式叙事跑团应用（双人实时 + 管理后台），非落地页。
- **受众**：玩家（手机端优先）、管理员/组织者（电脑端后台）。
- **语言**：纯极简黑白灰——`#000` 文字 / `#fff` 背景 / `#888` 次级 / `#e5e5e5` 边框 / `#f5f5f5` hover。禁用任何彩色（含烛火金/血红/暗紫）。无衬线字体（Inter via CDN，system-ui 兜底）。1px 描边，4-8px 小圆角，细字重 + 大量留白，间距走 8px 网格。
- **图标**：全部 lucide（CDN），1.5px stroke、16-20px、`currentColor`。每次 DOM 更新后必须 `lucide.createIcons()`。禁止任何自绘字符图标（`✦ ⚔ ❖` 等）。
- **三刻度**：`VARIANCE 4 / MOTION 2 / DENSITY 4`——克制微动效（hover、loader 旋转、视图淡入），`prefers-reduced-motion` 兜底。
- **反 slop**：无紫渐变、无玻璃态（无 backdrop-filter）、无衬线标题堆砌、无模板化卡片。
- **核心玩法**：AI 当 DM，看世界书实时编剧情；每回合返回叙事与双方选项。玩家提交自己的选择后，才能看到对方已经提交的具体选择。

## 1. 视图划分（6 个，单 SPA 内按角色/状态切换）

| # | 视图 | 标识 | 角色 | 说明 |
|---|---|---|---|---|
| 1 | 管理员登录 | `view-admin-login` | 管理员 | 账号 + 密码门禁，无注册。lucide: `user` / `lock` / `log-in` |
| 2 | 后台管理 | `view-admin-panel` | 管理员 | 世界书管理（内置列表/导入 .json/选中当前）+ 房间管理（创建→房间码/列表/进度/双方状态）。lucide: `book-open` / `upload` / `plus` / `eye` / `door-open` / `refresh-cw` / `x` |
| 3 | 玩家入口 | `view-player-entry` | 玩家 | 房间码 + 昵称进入，无需账号。lucide: `key-round` / `arrow-right` |
| 4 | 大厅 | `view-lobby` | 玩家 | 双玩家位（对方 mock 自动加入）、准备、开始。lucide: `check` / `play` / `users` / `copy` |
| 5 | 游戏主界面 | `view-game` | 玩家 | 核心视图，手机优先，详见 §2.4。lucide: `sword` / `heart` / `gem` / `scale` / `lock` / `eye-off` / `eye` / `chevron-right` / `sparkles` / `loader` |
| 6 | 结局 | `view-ending` | 玩家 | AI 结局 `{title,text}` + 本局回顾。lucide: `crown` / `history` / `rotate-ccw` |

> 顶部导航「玩家 / 管理员」切换角色入口；默认落地管理员登录（门禁优先）。管理员不参与玩家选择。

## 2. 布局要点

### 2.1 登录页 / 玩家入口
居中窄卡（max-width 440px），标题 + 副标题 + 表单，错误内联提示。mock 下任意非空账号密码可通过。

### 2.2 后台管理（桌面双栏 `1fr 1fr`，手机堆叠）
- **世界书面板**：内置世界书列表（`id/name/builtin/entryCount` + 描述）；当前世界书标记；「设为当前」；「导入世界书 (.json)」文件选择（前端解析并校验 `name`/`entries` 后上报内容）。
- **房间面板**：「创建房间」→ 生成 8 位房间码卡片（复制 + 进入演示）；房间列表（状态徽标 等待中/进行中/判定中/已结束、回合数、进度、双方姓名与就绪）；「查看进度」展开详情（进度条、双方状态、当前叙事、历史回合数、结局标题）；「关闭」房间；刷新按钮。

### 2.3 大厅
房间码（等宽间距大字 + 复制）、当前世界书名、双座位卡（自己 / 对方，mock 自动加入并准备）、准备按钮、开始按钮（双方就绪后可用）。

### 2.4 游戏主界面（核心，手机优先）
- 顶栏：房间码 | 回合序号 | 故事进度条 | 上下文窗口/当前占用 | 本次 Token（缓存图标与本次缓存 Token）| 本局总缓存率图标。
- DM 叙事区：`narrative`（左上角 DM · 第 N 回合标签）。
- 自己的选择区：本回合 `choices_A`/`choices_B` 按角色取，单选。
- 对方选择区：自己未提交时只显示“对方待选择/已完成选择”；自己提交后才显示对方已经提交的具体内容。
- 状态面板：自己的生命/资源/阵营（`story_state.A`/`.B`）；对方简化（生命/阵营），保证手机不挤。
- 角色资料、聊天和自定义行动均保留当前玩家的未提交草稿；对方保存资料、发送消息或提交行动时只局部更新对应状态，不重建本人的输入框，也不打断输入焦点。
- 操作栏状态机：`请先选择一项行动`（禁用）→ `提交选择`（`game:choice`）→ `已提交，等待对方选择…` → 自动推进 → `DM 正在编织剧情…`；真实失败时显示明确的`重新结算`按钮。任意一方开始重新结算后，服务端通过 `game:advance_started` 让双方立即移除旧按钮并同步为生成状态；前端等待时间覆盖完整思考与服务端重试，不能用短超时误报失败。只有玩家的行动文字明确要求结束故事时，AI 结局才会被采用。

#### 双人实时聊天胶囊（已实现）

- 游戏页面最下方增加一个悬浮的胶囊形聊天窗口，视觉参考苹果新UI的底部浮动胶囊。
- 两位玩家可以在游戏过程中实时发送和接收对话。
- 聊天通过独立的 `chat:send`、`chat:message`、`chat:history`、`chat:read` 事件局部更新，不触发游戏主界面重绘，也不进入 AI 上下文、世界书扫描或故事导出。
- 展开窗口后点击聊天区域以外的位置、切换标签页或浏览器窗口失焦时自动收回，避免遮挡游戏内容。
- 未读数量由服务端保存的双方已读游标计算；自己发出的每条消息显示“未读/已读”，只有对方在当前可见且获得焦点的聊天窗口中查看后才会变为“已读”。刷新或断线重连不会丢失这些状态。
- 进行中房间的最近 1000 条消息及双方已读游标随活动房间快照持久保存；玩家断线重连或服务重启恢复房间后仍可查看，房间结束时自动全部清除。

### 2.5 结局页
结局标题 + 结局文本；本局回顾时间线展示每回合叙事与双方实际选择；「再来一局」返回玩家入口。

## 3. 前端状态机

### 3.1 视图状态
```
state.view: 'admin-login' | 'admin-panel' | 'player-entry' | 'lobby' | 'game' | 'ending'
```

### 3.2 房间状态机（与后端一致）
```
lobby(等待加入/准备) → playing(回合循环) → judging(AI判定结局，mock 短瞬) → ended
```
- `playing` 回合内子状态：叙事+选项展示 → 各自选择（可并行）→ 双方提交 → 「AI 推进」→ 新叙事 + 新选项。
  - `judging`：玩家明确要求结束故事且 AI 生成结局时进入；故事进度到顶不会自动结束。

### 3.3 全局 appState（前端镜像）
```js
appState = {
  view,
  admin: { loggedIn, worldbooks:[{id,name,builtin,entryCount}], current, rooms, lastRoom },
  room: {        // 房间全量镜像（room:state 推送，按查看者提交状态过滤对方选择）
    id, code, status, worldbookId, worldbookName,
    round, progress, players:{A,B},   // { name, ready }
    storyState: { A:{name,hp,resources,alignment}, B:{...} },
    currentNode: { round, narrative, choices_A[], choices_B[], story_state, progress },
    submitted, choices, history, ending, createdAt,
  },
  me: { role: 'A'|'B', name },
  turn: { myChoiceId, submitted, oppSubmitted, oppChoiceText, advancing, judging },
}
```

## 4. 接口契约（先定，前端 mock 实现；后端严格按此实现便于联调）

> 核心数据约定：每回合节点 `{ round, narrative, choices_A[], choices_B[], story_state, progress }`。
> 选择可见性由服务端固定控制：玩家提交自己选择后，才接收对方的具体内容。
> `story_state` 由 AI 输出维护；结局文本由 AI 生成，前端只展示。

### 4.1 REST 路由（管理员门禁/后台；HttpOnly cookie 由浏览器自动携带）

| 方法 | 路径 | 入参 | 返回 |
|---|---|---|---|
| POST | `/api/auth/login` | `{ username, password }` | `{ ok, username }`（失败 401 `{ error }`） |
| POST | `/api/auth/logout` | — | `{ ok }` |
| GET | `/api/admin/worldbooks` | — | `{ worldbooks:[{ id,name,builtin,entryCount }], current }` |
| POST | `/api/admin/worldbooks` | `{ id?, name, content }`（content 为世界书 JSON 字符串或对象） | `{ id, name }` |
| POST | `/api/admin/worldbooks/:id/select` | — | `{ ok, current }` |
| POST | `/api/admin/rooms` | `{ worldbookId? }` | `{ roomId, code }` |
| GET | `/api/admin/rooms` | — | `{ rooms:[{ id,code,status,round,progress,worldbookId,players:{A:{name,ready},B:{name,ready}} }] }` |
| GET | `/api/admin/rooms/:id` | — | 房间详情（history/ending 等） |
| POST | `/api/admin/rooms/:id/close` | — | `{ ok }` |

> 未登录访问 `/api/admin/*` 返回 401 `{ error:"未登录" }` → 前端据此切回登录视图。

### 4.2 Socket.IO 事件

**客户端 → 服务端**

| 事件 | 载荷 | 说明 |
|---|---|---|
| `room:join` | `{ roomCode, name }` | 凭房间码 + 昵称加入，ack `{ ok, roomId, role }`（失败 `{ ok:false, error }`） |
| `room:ready` | — | 切换准备状态 |
| `game:start` | — | 双方就绪后开始 |
| `game:choice` | `{ choiceId }` | 提交本回合选择 |
| `game:advance` | — | 双方提交后请求 AI 推进（由「AI 推进」按钮触发） |

**服务端 → 客户端**

| 事件 | 载荷 | 说明 |
|---|---|---|
| `room:state` | `{ room }` | 房间全量同步；自己提交前剔除对方选择内容 |
| `player:joined` | `{ role, name }` | 对方加入 |
| `player:ready` | `{ role, ready }` | 对方准备状态 |
| `game:started` | 同 `game:round` 载荷 | 开场节点（可选，前端以 `game:round` 为准） |
| `game:choice_update` | `{ role, chosen, choiceText?, opponentChoiceText? }` | 选择状态；查看者尚未提交时不发送对方具体内容 |
| `game:round` | `{ round, narrative, choices_A, choices_B, story_state, progress }` | 新回合节点（扁平结构） |
| `game:ended` | `{ ending:{ title, text, history[] } }` | 结局；history 含每回合双方实际选择，供事后揭秘 |

> `game:judging` 为 **mock 附加事件**（后端可选发送，不依赖）：前端未收到时显示「编织中」直至 `game:ended`，收到则切换为「判定中」文案。

## 5. Mock 策略与 GameClient 抽象

### 5.1 抽象层 `GameClient`（`js/client.js`）
统一接口，业务只调 `window.client.xxx()`，不碰传输细节：
```js
class GameClient {
  // REST（管理员；未登录统一返回 { ok:false, error, status:401 }）
  login({username,password})   // → {ok,username}
  logout()                     // → {ok}
  listWorldbooks()             // → {worldbooks, current}
  importWorldbook({name,content}) // → {id,name}
  selectWorldbook(id)          // → {ok,current}
  createRoom({worldbookId})    // → {roomId,code}
  listRooms()                  // → {rooms:[...]}
  getRoom(id)                  // → {room}
  closeRoom(id)                // → {ok}
  // Socket（玩家）
  join({roomCode,name})        // → ack {ok,roomId,role}
  setReady() / startGame() / submitChoice(choiceId) / advance()
  on(event, cb) / off(event, cb)   // 事件名对齐 4.2
}
```

### 5.2 两个实现
- **`MockClient`（默认）**：内存态模拟完整链路，`setTimeout` 模拟网络/AI 延迟。管理员任意非空凭据通过；创建房间生成 8 位房间码；玩家凭码加入，对方（bot）自动加入并准备、每回合自动选择。每次推进从场景池随机取材并生成双方选项；选择内容同样在自己提交后才显示，故事进度到顶不会自动结束。
- **`SocketClient`（预留）**：`fetch`（`credentials:'include'` 携带 HttpOnly cookie）+ `socket.io`（CDN），方法签名与事件名与 MockClient 完全一致；`room:join` 以 ack 回调返回。前端顶部 `USE_MOCK` 开关切换，业务零改动。

```js
const USE_MOCK = true;   // 接真后端时改为 false
window.client = USE_MOCK ? new MockClient() : new SocketClient();
```

> mock 局限：单浏览器单会话（`client.me` 全局唯一），适合单机演示「我 + bot」；双浏览器双玩家场景属于真实后端职责。bot 仅在玩家占 A 位时自动补 B。

## 6. 世界书导入流程（前端）

1. 管理员在后台点「导入世界书 (.json)」→ `<input type="file" accept=".json">` 选文件。
2. 前端 `file.text()` 读取并 `JSON.parse`，校验顶层 `name`（string）与 `entries`（object），兼容 SillyTavern 格式（见 `worldbook/README.md`）。
3. 解析/校验失败：内联提示「导入失败：JSON 解析错误或格式不符」；成功：调 `client.importWorldbook({ name, content: parsed })`（content 原样上报，mock 仅内存登记）。
4. 列表刷新显示新世界书（`entryCount`），可「设为当前」——新建房间默认使用当前世界书。

## 7. 管理员 / 玩家分工

| | 管理员 | 玩家 |
|---|---|---|
| 凭据 | 账号 + 密码（唯一账号，无注册，HttpOnly cookie） | 房间码（8 位大小写数字）+ 昵称（无需账号） |
| 端 | 电脑端优先 | 手机端优先 |
| 职责 | 门禁、世界书管理（内置/导入/选中）、创建房间生成房间码、旁观房间进度与双方状态 | 凭房间码加入、准备、开始、每回合做选择 |
| 权限边界 | 组织者/旁观，**不参与玩家选择**，不占玩家位（后台「进入演示」仅用于单机演示流程） | 不可访问后台 |

## 10. 接入后端时的注意点
- `js/client.js` 顶部 `USE_MOCK` 改 `false` 即切 SocketClient，方法签名与事件名不变；socket.io CDN 脚本已在 `index.html` 引入。
- 选择可见性：服务端必须在 `room:state` / `game:choice_update` 中按查看者过滤；自己提交前只知道对方是否完成，自己提交后才收到对方选择内容。
- 结局必须服务端生成（含 history 的双方实际选择），前端只渲染；`game:judging` 为可选事件。
- 管理员鉴权：登录态由 HttpOnly cookie 维护；前端收到任意 `/api/admin/*` 的 401 即切回登录视图。
- `game:round` 载荷为扁平结构（非嵌套 node）；选择可见性不再由 AI 字段控制。
- mock 中 `game:choice_update` 的可见性、bot 行为等为演示简化，真实后端以服务端广播为准。
