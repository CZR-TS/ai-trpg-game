# 方案设计：AI 双人跑团游戏

## 1. 核心理念

把 **SillyTavern（酒馆AI）** 的角色扮演能力，与 **桌面跑团（TRPG）** 的多人协作机制结合：

- AI = DM（地下城主 / 主持人），负责叙事、判场、推进剧情。
- 两位玩家 = 故事中的两位主角，每回合各自做出选择。
- 世界书 = 预设的世界观、物品、地点、NPC 库，按需注入 AI 上下文。

## 2. 三种回合机制（融合）

为让剧情"复杂好玩"，本游戏支持三类回合，由 AI 根据剧情节点选择使用：

### 2.1 合作回合（Co-op）
- 两人为队友，共同面对挑战。
- 每人给出一个行动，AI 综合两人行动推进剧情。
- 例：A 选择"正面吸引怪物注意"，B 选择"绕后偷袭"——AI 判定配合是否成功。

### 2.2 对抗回合（Versus）
- 两人利益冲突，竞争同一目标。
- 各自选择后，AI 评判本回合谁占上风，累计优势点。
- 例：争夺唯一的圣剑，A"抢先夺取"，B"设陷阱阻拦"。

### 2.3 同时选择回合
- 两人先各自提交选择；自己提交之前只能看到对方是否完成，自己提交之后才能看到对方的具体选择。
- AI 根据两人选择的**组合**触发不同分支（类似博弈支付矩阵）。
- 例：审讯时 A/B 可选"坦白/沉默"，(坦白,坦白)/(坦白,沉默)/(沉默,沉默) 三种结局。

> 三类回合在剧情中交替穿插，由 DM(AI) 根据当前场景选择类型并告知玩家。

## 3. 数据流（一回合）

```
玩家A选择 ─┐
            ├─→ 后端汇总 → 拼Prompt(角色卡+世界书激活条目+历史) → 调LLM
玩家B选择 ─┘                                                        │
     ←────────── 剧情文本 + 下回合选项 + 状态变更 ──────────────────┘
```

## 4. 状态机（房间）

```
创建房间 → 等待玩家加入 → 展示世界书固定背景 → 创建角色 → [选择中 → AI推进]循环 → 结局判定 → 结束
```

房间持久化字段：

- roomId, 房主, 玩家列表(2)
- 当前世界书 + DM 角色卡
- 剧情历史（消息数组）
- 两人累计状态（生命/资源/优势点/阵营倾向等，由 AI 输出结构化数据维护）
- 当前进度 / 章节标志

## 5. Prompt 结构（每回合）

```
[System]
  DM 角色卡（描述/性格/场景/系统指令）
  + 世界书【常驻】条目（蓝圈）
  + 世界书【关键词激活】条目（按本回合对话扫描得出）
  + 输出格式约定（JSON: 剧情文本 + 下回合选项 + 状态变更）
[历史消息]
  开场 → 上一回合剧情
[当前回合]
  本回合 A 的选择 / B 的选择 + 回合类型
```

AI 被要求返回结构化 JSON，便于前端渲染选项与维护状态。

## 6. 结局机制

- 每回合 AI 返回一个 `story_state`（章节进度 + 双方阵营值 + 关键标志位）。
- `progress` 只表示故事进展，达到 1.0 不会自动结束；只有玩家在本回合行动中明确要求结束故事时，后端才允许 AI 返回并采用完整结局。
- 结局由"全程选择的综合"决定，不同选择组合 → 不同结局。

## 7. 技术架构

```
浏览器A ─┐
         ├─ WebSocket(Socket.IO) ─┐
浏览器B ─┘                         │
                                   ├─ Express 服务
                                   │    ├─ 房间/状态管理
                                   │    ├─ 世界书引擎
                                   │    └─ LLM 调用层(OpenAI兼容)
                                   └─ 内存/文件持久化
```

## 8. 后续路线

1. MVP：单世界书 + 合作回合 + 双人同步 + AI 叙事（先跑通闭环）
2. 加入对抗 / 暗中选择回合
3. 世界书可视化编辑器
4. 多世界书 / 多剧本切换
